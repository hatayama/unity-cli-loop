# Package Manager Distribution

## Channel policy

The Homebrew tap (`hatayama/homebrew-tap`) updates on every dispatcher release,
including beta tags. There is no separate stable-only formula yet.

winget receives stable dispatcher releases only. Prereleases are not submitted.

## Components

| Piece | Role |
| --- | --- |
| `hatayama/homebrew-tap` / `Formula/uloop.rb` | Published formula. Generated by release automation — do not edit by hand. |
| `cli/release-automation/cmd/update-homebrew-formula` | Renders the formula from the dispatcher release assets and pushes it to the tap. |
| `.github/workflows/dispatcher-publish.yml` `post-publish` step | Runs the update command after a successful dispatcher publish. |
| `HOMEBREW_TAP_TOKEN` repository secret | Fine-grained PAT scoped to `hatayama/homebrew-tap` with Contents Read and write. Used only for tap writes; release asset reads use the workflow `GITHUB_TOKEN`. |
| `microsoft/winget-pkgs` / `manifests/h/hatayama/uloop/` | Published winget manifests. Generated by release automation — do not edit by hand. |
| `cli/release-automation/cmd/update-winget-manifest` | Renders the version, installer, and locale manifests and opens an upstream pull request. |
| `.github/workflows/dispatcher-publish.yml` `Open winget-pkgs pull request` step | Submits a new manifest pull request after a successful stable dispatcher publish. |
| `WINGET_PKGS_TOKEN` repository secret | Classic PAT with `public_repo`. Used to push branches to `hatayama/winget-pkgs` and open pull requests against `microsoft/winget-pkgs`; release asset reads use the workflow `GITHUB_TOKEN`. |

## Operations

- When `HOMEBREW_TAP_TOKEN` is unset, the update command logs an explicit skip and
  exits 0 so the dispatcher release still succeeds.
- A red `post-publish` Homebrew step does not affect already-uploaded release
  assets. Re-run that workflow run; formula updates are idempotent.
- When `WINGET_PKGS_TOKEN` is unset, the winget update command logs an explicit
  skip and exits 0. It also skips prereleases, versions that already exist
  upstream, and versions with an open submission pull request.
- New winget-pkgs pull requests must pass the upstream bot validation and human
  moderation. Moderation commonly takes several days and can take up to two
  weeks.
- `uloop update` refuses Homebrew-managed installs and directs users to
  `brew upgrade uloop`. The dispatcher freshness path does the same for required
  updates and skips optional auto-updates.
- `uloop update` will also refuse winget-managed installs and direct users to
  `winget upgrade --id hatayama.uloop`.
- The Unity Settings window and the Setup Wizard offer no CLI action for a
  Homebrew-managed install: the primary button is disabled and reads
  `Managed by Homebrew`. Installing from Unity would place a second, package-owned
  binary in `~/.local/bin` while brew keeps its own on PATH. When such an install is
  below the pin minimum, a warning block above the button names the required version
  and the selectable `brew upgrade uloop` command so the disabled button is not a
  dead end. A Homebrew binary that answers no version probe, or that reports a
  version at or above the minimum yet does not answer as the dispatcher, points at
  `brew reinstall uloop` instead — upgrading it would report nothing to do. PATH
  repair is the one action that survives the
  stand-down, because it writes no binary and only makes an already installed
  package-owned CLI reachable.
- The Unity Settings window and Setup Wizard will display `Managed by winget`
  for a winget-managed CLI and will not overwrite it.

## Known follow-ups

1. After a stable channel exists, decide whether formula updates should gate on
   non-prerelease tags or whether a separate `uloop@beta` formula is needed.
   Until then, beta releases keep advancing the single formula.
2. If the winget moniker `uloop` conflicts with another package, remove `Moniker`
   from the locale manifest. Do not change `PackageIdentifier`.
